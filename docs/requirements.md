# 需求確認（本人 2026-11-10）

M0 規格原本卡在「使用者確認規格」。這份記下本人實際給的方向，取代之前的待確認狀態。

## 一、與舊 WP_Themes 的關係：同一個 repo，改名接手

原本寫的是「不取代 WP_Themes」。2026-11-10 下午把這個決定改掉了，因為它的前提不成立：

- WP_Themes 是 2026-08-04 一個 commit 產的骨架——母佈景 1890 行傳統 PHP，四個子佈景各 48 行
  空殼（連 `functions.php` 都沒有），之後三個月沒再動。
- 本人確認：沒有任何正式網站在用這些佈景。
- 「十套配色在後台任意切換」靠的是 Style Variations，那是 Block Theme 的機制；
  傳統 PHP 佈景做不到。所以舊程式碼沒有重用價值。

做法是**沿用 repo、改名、換內容**：`Chienfu168/WP_Themes` → `Chienfu168/futheme`，
本機 `03-Websites/WP_Themes` → `03-Websites/futheme`。舊程式碼留在 git 歷史裡（commit `b58ca3b`）。

🔑 **為什麼不另開一個 repo**：共用佈景的價值就在於只有一套。開第二個 repo 等於親手製造
第二條線，之後每次改版型都要先問「這次改哪邊」。原本列為紅旗的「釐清界線」因此消失——
不是解決了，是不存在了。

## 二、架構：依 WordPress 佈景規範，在其上增修

不自創一套機制。以 WordPress 原生的 Block Theme 規範為基礎：
`theme.json`、`templates/`、`parts/`、`patterns/`、Style Variations、Global Styles。

這條在實作時的具體意義：
- 能用原生做到的，不要自己寫 PHP 或 JS
- 不做自訂設定頁、不做配色資料表、前台不跑配色計算
- 使用者在網站編輯器改過的東西，優先序高於檔案——更新檔案不等於網站外觀跟著變

## 三、配色：後台可任意切換

十套配色以 Style Variations 實作，管理員在「外觀 → 編輯器 → 樣式」切換，
不需要改碼、不需要重新部署。

- 預設 `urban-blue`；十套裡仍保留它，讓人可以明確切回來
- 切換是站台層級的選擇，不是每頁設定
- 手動改主色不保證其他色自動調整——改了要自己檢查對比（風險文件已列）

## 四、版型：這一版要做哪些

| 項目 | 說明 |
| --- | --- |
| 頁首 | 共用 template part；含網站識別與主選單 |
| 頁尾選單 | 共用 template part |
| 首頁 | 自訂首頁版型（front-page） |
| 一般頁面 | `page` 版型 |
| 多文章頁面 | 彙整／列表（`index`、`archive`、`search`） |
| 單篇文章 | `single` |
| 單一頁面 | 同「一般頁面」，但含下方的頁首橫幅 |

## 五、橫幅圖片：這是區隔各站風格的主要手段

**首頁橫幅**：每個網站用自己的圖，這是各站長得不一樣的主要來源。
配色換的是色調，橫幅換的是氣質——兩者一起，同一套佈景才撐得起風格差異明顯的網站。

**單篇文章／單一頁面的頁首橫幅**：文章與頁面上方的橫幅圖。

🔑 **實作原則：橫幅是「內容」，不是「佈景程式碼」。**

圖片必須由各站管理員在後台換，不能寫死在佈景檔案裡——否則每加一個網站就要改一次佈景，
而那正是共用佈景要消滅的事。做法是做成 template part 或 pattern，圖片存在各站自己的媒體庫，
佈景只提供版位與樣式。

同時要處理：
- 沒有設定橫幅時的 fallback（不能破版、不能出現空白區塊或裂圖）
- 不同比例與尺寸的裁切行為，以及手機上的顯示
- 橫幅上有文字時的對比（十套配色都要能看）
- 圖片效能：尺寸、格式與延遲載入要納入效能預算
